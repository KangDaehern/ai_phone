# 구현 전 확인사항

아래 정보가 있어야 실제 구조와 견적을 확정할 수 있다.

## 최우선: 현재 전화 환경

- 대표전화 통신사와 상품명
- 대표번호가 일반 전화, 인터넷전화(VoIP), SIP 트렁크 중 무엇인지
- 사무실 PBX/키폰 주장치 제조사와 정확한 모델명
- 직원 전화기 제조사와 모델명
- 내선번호 목록
- 현재 통화 전환 방법과 무응답 시 동작
- 발신번호가 PBX까지 전달되는지
- SIP 계정 또는 외부 연동 API를 통신사가 제공하는지
- 대표번호 유지가 필수인지, 번호이동이 가능한지

## 운영 정책

- 업무시간과 휴무일 안내 방식
- AI임을 첫 안내에서 밝힐지
- 통화 녹음을 할지, 전사와 요약만 저장할지
- 보관 기간과 삭제 요청 처리 방식
- 연결 제한 시간: 현재 가정은 약 10초
- 담당자 부재/휴가 상태를 누가 어떻게 입력할지
- AI 오판 시 기본 연결할 `etc` 담당자와 순환 규칙
- 직원이 동시에 통화 중일 때의 처리

## 데이터 준비

- 직원별 이름, 내선, 담당 업무, 대체 담당자
- 기존 고객사와 전화번호, 담당자 목록
- 자주 발생하는 전화 용건 예시 50~100개
- 실제 직원이 사용하는 연결 판단 규칙
- 고객명·회사명·직원 이름의 다양한 발음과 별칭

## 알림 방식

- 카카오톡이 반드시 필요한지
- 각 직원이 카카오 로그인과 앱 권한 동의 절차를 수행할 수 있는지
- 카카오 비즈니스 채널과 알림톡 공식 딜러 계약을 사용할 의향이 있는지
- 이메일, 사내 웹 알림, 문자 또는 다른 메신저도 가능한지

## 인프라와 예산

- 사무실 인터넷 장애 빈도와 이중 회선 여부
- 24시간 켜둘 Windows 장비 제공 여부
- 동시 통화 최대 수
- 월간 대표전화 수와 평균 통화 시간
- 클라우드 AI/API 및 통신 비용 허용 범위
- 원격 유지보수 가능 여부

## 첫 기술 검증의 합격 조건

- 실제 또는 테스트 SIP 전화가 AI로 들어온다.
- 한국어 응답 지연이 통화에 불편하지 않다.
- 발신번호를 안정적으로 얻는다.
- 지정 내선으로 전환할 수 있다.
- 내선 무응답을 감지해 AI 또는 메모 흐름으로 복귀할 수 있다.
- 통화 장애 시 사람에게 우회된다.
