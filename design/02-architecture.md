# 시스템 구조 초안

## 결론

구현은 가능하다. 단, 현재 대표전화와 사무실 교환기가 SIP 트렁크, 내선 호출, 통화 전환 및 무응답 회수 기능을 제공하는지가 선행 조건이다. AI 기능만으로 기존 전화선을 직접 제어할 수는 없다.

## 권장 논리 구조

```text
외부 발신자
    │
통신사 대표번호 / SIP 트렁크
    │
PBX 또는 전화 게이트웨이
    ├── 등록 번호 → 담당자 내선 호출
    │                  └── 무응답 → AI 응대
    └── 미등록 번호 → AI 음성 응대
                          │
                    라우팅 서비스
                    ├── 직원·역할 규칙
                    ├── 고객·전화번호 이력
                    └── 담당자/대체 담당자 결정
                          │
                    PBX 콜 전환
                          │
                    통화 요약·알림
```

## 구성 요소

### 1. 전화/PBX 계층

- 대표번호 수신
- 발신번호(CID) 전달
- 내선 호출 및 콜 전환
- 10초 무응답 감지
- AI로 통화 회수 또는 음성사서함 형태의 재응대
- 장애 시 기존 내선이나 휴대전화로 우회

후보 형태는 기존 IP-PBX 연동, Asterisk/FreeSWITCH 같은 소프트웨어 PBX, 또는 통신사의 클라우드 PBX다. 선택은 현재 전화 계약과 장비 확인 후 결정한다.

### 2. 실시간 음성 AI 계층

- SIP 또는 미디어 스트림으로 음성을 수신한다.
- 짧고 자연스러운 한국어 안내와 질문을 수행한다.
- 발신자 발언에서 회사명, 이름, 용건, 찾는 담당자를 구조화한다.
- 라우팅 서비스 도구를 호출하고 결정된 SIP URI나 내선으로 전환한다.
- 음성 스타일은 특정 개인의 목소리를 복제하지 않고, 차분하고 간결한 성인 음성으로 정한다.

OpenAI Realtime API는 SIP 수신과 통화 refer 기능을 제공하므로 후보가 될 수 있다. 실제 전화번호를 Realtime API에 직접 꽂는 것이 아니라, 통신사/PBX가 SIP 통화를 전달할 수 있어야 한다.

### 3. 라우팅 서비스

AI와 분리된 결정 엔진으로 구현한다.

우선순위 예시:

1. 정확히 일치하는 발신번호의 고정 담당자
2. 고객사에 지정된 기본/보조 담당자
3. 발신자가 명시한 직원
4. 용건·직원 역할 규칙
5. `etc` 담당자

초기 버전에서는 데이터베이스 규칙으로 결과를 만들고, AI는 발화 이해와 필요한 추가 질문에 집중하게 한다.

### 4. 데이터와 관리 화면

- 직원과 내선 관리
- 고객사와 여러 전화번호 관리
- 담당자 및 대체 담당자 관리
- 업무 키워드와 역할 관리
- 통화 기록, 연결 결과, 요약 확인
- 잘못 연결된 건을 수정해 다음 통화에 반영

초기에는 SQLite로 시험할 수 있으나 여러 PC, 백업, 동시 사용을 고려하면 운영 단계에는 PostgreSQL 같은 서버형 DB가 적합하다.

### 5. 알림 계층

담당자에게 발신번호, 회사/이름, 용건, 연결 결과, 회신 필요 여부를 보낸다.

카카오톡 일반 메시지 API는 같은 서비스 사용자와 권한·동의 조건이 있어 사내 임의 계정으로 자유롭게 자동 전송하는 용도에는 제약이 크다. 운영 후보는 다음 순서로 검토한다.

1. 사내용 웹/Windows 알림 또는 이메일
2. 카카오 알림톡: 비즈니스 채널, 템플릿 및 공식 딜러 계약 검토
3. 카카오톡 메시지 API: 모든 직원의 카카오 로그인·동의와 앱 심사가 가능한 경우
4. 사내 메신저 웹훅 또는 문자 메시지

PC 카카오톡 화면을 매크로로 조작하는 방식은 장애와 계정 제재 위험 때문에 운영 구조로 권장하지 않는다.

알림톡은 담당자 통화 요약뿐 아니라 의심 스팸 검토에도 사용한다. 알림톡에는 민감한 전체 통화 내용이나 직접 변경용 비밀 토큰을 넣지 않고, 발신번호·분류 사유·짧은 요약과 인증된 관리화면 링크만 제공한다. 스팸 확정이나 정상 번호 복구는 로그인된 관리화면에서 처리하고 변경 이력을 남긴다.

## 확정된 운영 모듈

- 담당자 연결 전 사전 안내 및 수락/거절/재배정
- 직원 휴가·회의·외근·통화중 상태 관리
- `미확인 → 확인 → 회신 완료` 콜백 업무함
- 신뢰도 기반 자동 연결·재확인·`etc` 담당자 연결
- VIP·주의 고객·자동 스팸 차단과 사람의 피드백 루프
- 업무시간·휴일·긴급전화 라우팅
- 잘못 연결된 번호의 수정 및 다음 통화 반영
- AI 장애 시 기존 전화 흐름으로 전환하는 수동/자동 비상 스위치
- 통화량·오연결률·회신율·AI 비용 관리 화면
- 음성 인식 실패 시 DTMF 내선 입력

## 서버가 필요한가

상시 운영되는 프로세스는 필요하다. 다만 반드시 별도의 물리 서버를 구매해야 하는 것은 아니다.

### 권장 운영 형태

- 사무실에서 이미 24시간 운영 중인 Windows 서버 PC: 성능과 안정성이 충분하면 새 장비를 구매하지 않고 PBX/게이트웨이 연동, 라우팅 서비스와 로컬 캐시를 실행
- 외부 클라우드 서비스: 실시간 음성 AI, 선택적으로 데이터베이스/백업
- 정전·인터넷 장애 시: 통신사 또는 PBX에서 기존 내선/휴대전화로 우회

Windows 일반 직원 PC 한 대에서 실행할 수도 있지만 재부팅, 절전, 사용자 로그아웃, 업데이트로 전화가 끊길 수 있으므로 운영용 상시 장비를 분리하는 편이 안전하다. Windows Service나 컨테이너로 자동 시작하고 상태 감시를 둔다.

완전 로컬 AI도 이론적으로 가능하지만, 자연스러운 한국어 실시간 응답과 낮은 지연시간을 안정적으로 제공하려면 GPU, 모델 운영, 음성 인식·합성까지 관리해야 하므로 첫 버전에는 클라우드 음성 AI가 현실적이다.

## 장애 안전성

- AI 장애 또는 응답 지연 시 `etc` 내선으로 즉시 전달
- 인터넷 장애 시 기존 전화 착신 규칙으로 우회
- 잘못된 라우팅을 직원이 바로 수정할 수 있게 함
- 모든 외부 API 호출에 타임아웃과 재시도 한도 적용
- 통화 연결 경로와 데이터 저장 경로를 분리

## 보안·개인정보

발신번호, 음성, 녹취, 요약은 개인정보가 될 수 있다. 개발 전에 다음을 확정해야 한다.

- AI 응대 및 녹음/전사 고지 문구
- 수집 목적과 법적 근거
- 녹음·전문·요약 각각의 보관 기간과 파기 방법
- 외부 AI 및 메시징 업체로 전달되는 데이터와 국외 처리 여부
- 직원별 열람 권한, 암호화, 접근 로그 및 백업 정책
- 세무 관련 민감 정보가 통화에 포함될 때의 최소 수집 원칙

법률 판단은 실제 운영 방식과 계약에 따라 달라질 수 있으므로 출시 전에 개인정보/통신 분야 전문가의 검토가 필요하다.

### 법률 검토 담당 방침

사용자는 내부 법률가를 통해 개인정보와 통신 관련 검토를 진행한다. 개발팀은 내부 법률가가 판단할 수 있도록 다음 자료를 제공하고, 승인된 정책을 요구사항과 테스트 항목에 반영한다.

- 전체 통화 및 데이터 흐름도
- 수집하는 데이터 항목과 수집 목적
- OpenAI, 카카오 알림톡 딜러, 통신사 등 외부 처리업체 목록
- 국내외 저장·처리 위치와 업체별 보관 정책
- AI 응대, 녹음 및 전사 고지 문구 후보
- 녹음, 전문, 요약, 발신번호별 보관 기간과 자동 파기 방식
- 직원별 접근 권한과 감사 로그 정책
- 정보주체의 열람·정정·삭제 요청 처리 절차
- 사고 대응 및 외부 업체 계약서의 개인정보 관련 조항

법률 검토가 완료되기 전에는 실제 고객 통화를 녹음하거나 장기간 보관하는 운영을 시작하지 않는다. 개발용 데이터는 가명 또는 합성 데이터를 사용한다.

## 단계별 구현 제안

### 0단계: 전화 환경 조사

현재 통신사, 대표번호 방식, PBX 모델, 전화기 모델, SIP 지원, 전환 코드를 확인한다.

### 1단계: 전화 없는 시뮬레이터

직원·고객·역할 데이터와 텍스트 입력만으로 라우팅 결과를 검증한다.

### 2단계: 테스트 SIP 번호

별도 테스트 번호로 AI 수신, 짧은 대화, 내선 한 곳 연결을 검증한다.

### 3단계: 부재 처리와 알림

10초 무응답 회수, 메모, 요약, 웹/이메일 알림을 붙인다.

### 4단계: 제한 운영

일부 시간 또는 일부 고객에만 적용하고 오연결률, 응답 지연, 통화 비용을 측정한다.

### 5단계: 대표번호 전환

장애 우회와 개인정보 정책을 검증한 후 전체 대표번호에 적용한다.
