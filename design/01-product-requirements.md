# 제품 요구사항

## 현재 구현 상태

대표 1명과 직원 9명, 더미 업체 27개를 기준으로 로컬 시뮬레이터를 구현했다. 전화/PBX, OpenAI 음성 API와 카카오 알림톡은 미계약 상태이므로 더미 어댑터로 대체한다. 실제 외부 서비스 없이 등록번호·업체명·대표 요청·직원 상태·스팸·무응답 흐름을 자동 테스트할 수 있다.

## 해결하려는 문제

직원 5~20명 규모의 세무·회계 사무실에서는 대표전화로 걸려오는 전화 대부분에 실제 담당자가 따로 있다. 현재는 누군가가 먼저 전화를 받고 용건을 확인한 뒤 담당자에게 돌려야 하며, 이 반복 업무를 AI 교환원으로 자동화한다.

## 주요 사용자

- 외부 고객과 거래처
- 세무사·회계사 및 일반 직원
- 직원, 역할, 고객 담당 관계를 관리하는 사무실 관리자

## 핵심 통화 흐름

### 등록된 발신번호

1. 발신번호로 고객과 담당자를 조회한다.
2. 담당자 내선으로 즉시 연결한다.
3. 약 10초 동안 응답이 없으면 AI 응대로 회수한다.
4. AI가 부재 안내 후 용건과 회신 정보를 확인한다.
5. 요약을 담당자에게 전달한다.

### 미등록 또는 담당자가 불명확한 발신번호

1. AI가 대표전화를 받으며 AI 상담 및 필요 시 녹음 사실을 고지한다.
2. 발신자의 회사명, 이름, 찾는 사람, 용건을 간결하게 확인한다.
3. 고객 담당 이력, 전화번호 매핑, 직원 역할 규칙으로 담당자를 결정한다.
4. 확신도가 낮으면 추가 질문을 한 번 하거나 `etc` 담당자에게 연결한다.
5. 담당자 연결 실패 시 메모를 받고 요약을 전송한다.

## 업무 규칙

- 정확한 담당자 연결이 긴 상담보다 우선이다.
- 발신자가 사람과의 통화를 요청하면 불필요한 대화를 늘리지 않는다.
- 세무·회계 판단이나 확정적인 전문 상담을 AI가 대신하지 않는다.
- 담당자 결정 근거와 연결 결과를 감사 로그에 남긴다.
- 잘못된 자동 연결을 줄이기 위해 초기에는 규칙 기반 라우팅을 우선하고 AI 판단은 보조로 사용한다.

## 필수 운영 기능

다음 기능은 향후 선택 기능이 아니라 제품의 필수 범위로 한다.

### 담당자 연결 전 사전 안내

- 고객을 담당자에게 연결하기 전에 담당자에게 `A회사 홍길동, 부가세 신고 문의` 형식으로 회사명, 이름과 용건을 알려준다.
- 담당자는 통화를 수락하거나, 거절하여 부재 메모로 전환하거나, 다른 담당자에게 재배정할 수 있어야 한다.
- 고객에게는 담당자 연결 중이라는 짧은 안내와 대기음을 제공한다.

### 직원 상태 반영

- 휴가, 회의, 외근, 통화 중, 자리 비움, 업무 종료 상태를 라우팅에 반영한다.
- 부재 상태에는 종료 예정 시각과 대체 담당자를 지정할 수 있어야 한다.
- 초기에는 관리 화면에서 수동으로 설정하고, 이후 캘린더 연동을 지원한다.

### 콜백 업무함

- 담당자가 받지 못한 전화는 `미확인 → 확인 → 회신 완료` 상태로 관리한다.
- 담당자 변경, 메모 추가, 우선순위, 회신 기한과 처리 이력을 제공한다.
- 미확인 상태가 오래 지속되면 담당자와 관리자에게 재알림한다.

### 라우팅 신뢰도

- 신뢰도가 높으면 자동 연결한다.
- 신뢰도가 중간이면 고객에게 담당자 또는 용건을 한 번 재확인한다.
- 신뢰도가 낮거나 적절한 담당자가 없으면 사전에 지정된 `etc` 담당자에게 연결한다.
- AI가 선택한 담당자와 선택 근거를 기록한다.

### VIP·스팸·주의 고객

- VIP는 우선 연결하고, 담당자가 부재면 지정된 대체 담당자에게 연결한다.
- 주의 고객은 숙련 담당자 또는 관리자에게 연결한다.
- 확정 스팸 번호는 AI가 자동 차단하고 직원 전화기를 울리지 않는다.
- 의심 스팸은 AI가 용건을 최소 확인한 후 연결하지 않고, 스팸 검토 담당자에게 알림톡을 보낸다.
- 스팸 검토 알림에는 발신번호, 수신 시각, AI 분류 사유와 짧은 요약을 포함한다.
- 스팸 검토 담당자는 알림의 안전한 관리화면 링크에서 다음 중 하나를 선택할 수 있어야 한다.
  - `스팸 확정`: 이후 자동 차단
  - `정상 번호`: 스팸 표시 해제 및 필요 시 고객/담당자 등록
  - `이번만 차단`: 영구 차단하지 않고 해당 통화만 종료
  - `주의 번호`: 다음 통화부터 지정 담당자에게 제한 연결
- 사용자가 말한 막내 역할을 기본 스팸 검토 담당자로 설정할 수 있지만, 관리자 화면에서 다른 직원 또는 순환 담당자로 변경할 수 있어야 한다.
- 알림톡 자체의 버튼만으로 민감한 변경을 확정하지 않고, 인증된 관리화면에서 최종 처리한다.
- 발신번호 변조 가능성을 고려해 번호 하나만으로 중요한 고객을 확정하지 않는다.

### 시간 정책과 긴급전화

- 업무시간, 점심시간, 휴일과 임시 휴무 정책을 설정한다.
- 업무시간 외에는 기본적으로 메모를 받고 다음 영업일 회신을 안내한다.
- 사전에 정의한 긴급 용건만 당직자 또는 긴급 담당자에게 연결한다.

### 라우팅 수정 학습

- 잘못 연결된 번호를 직원이 고객과 올바른 담당자로 수정할 수 있어야 한다.
- 수정은 다음 통화부터 규칙에 반영하되, 변경자와 변경 이력을 기록한다.
- 반복 오연결이 발생하면 관리자 검토 항목으로 올린다.

### 장애 비상 스위치

- 관리자는 AI 응대를 즉시 중지하고 기존 대표전화 흐름으로 전환할 수 있어야 한다.
- AI, 인터넷, 데이터베이스 또는 외부 API 장애를 자동 감지하면 사전에 지정된 내선·휴대전화·기존 착신 그룹으로 우회한다.
- 장애와 복구 시각을 관리자에게 알린다.

### 운영 관리 화면

- 시간대별 통화량, 자동 직결률, AI 응대율, 오연결률을 제공한다.
- 담당자 응답시간, 부재 메모 수, 회신 완료율과 지연 건수를 제공한다.
- AI 통화시간, 건별·일별·월별 AI 비용과 예산 대비 사용률을 제공한다.
- 스팸 차단 수, 오탐 복구 수와 사용자 피드백 결과를 제공한다.

### DTMF 보조 입력

- 음성 인식 신뢰도가 낮거나 고객이 원하면 전화 버튼 입력으로 전환한다.
- 고객이 내선번호를 알면 직접 입력할 수 있게 한다.
- 입력 실패 횟수가 기준을 넘으면 `etc` 담당자 또는 부재 메모로 전환한다.

## 저장할 데이터 초안

- 직원: 이름, 내선, 역할, 담당 업무, 근무/부재 상태, 알림 대상
- 고객: 회사명, 전화번호 목록, 기본 담당자, 보조 담당자
- 라우팅 규칙: 키워드, 업무 종류, 우선 담당자, 대체 담당자
- 통화: 발신번호, 시간, 연결 결과, 담당자, 요약, 후속 조치
- 선택 데이터: 녹음 파일과 전문. 법적 근거와 보관정책 확정 전에는 기본 저장 대상으로 간주하지 않는다.

## 성공 기준 초안

- 등록된 고객의 대부분을 AI 대화 없이 올바른 담당자에게 연결한다.
- 미등록 고객의 용건 파악과 연결이 짧은 시간 안에 끝난다.
- 연결 실패 시 담당자가 발신자, 용건, 회신 필요 여부를 즉시 확인할 수 있다.
- AI 또는 외부 서비스 장애 시 기존 대표전화 업무가 완전히 중단되지 않는 우회 경로가 있다.
